CGA-alone 개발 기능 사용 안내

목차
  • 봇을 만드는 사람
  • 질문하는 사람과 공유방
  • 연결 클라이언트와 템플릿
  • 확인된 범위와 사용 전 확인

이 안내는 CGA-alone의 변경 기능을 기존 CGA 매뉴얼에 보충합니다. 기존 운영·제작·API·관리 메뉴, 의도/모듈·개체·흐름·변수·Rich Form·카카오 카드·다국어·그룹권한·라이선스·버전 관리는 계속 사용합니다. 원본 Word/PDF와 다른 언어 매뉴얼에는 아직 이 보충 내용이 반영되지 않았습니다.

봇을 만드는 사람

  1. 제작자 계정으로 로그인해 본인의 봇 하나를 생성합니다. 처음 정한 봇 이름을 표시 이름과 호출 이름으로 함께 사용합니다. 이미 본인 봇이 있으면 해당 봇을 편집합니다.
  2. 원래 의도/모듈 화면에서 사전 질문과 답변을 작성합니다. 1차 엔진은 ML 또는 시멘틱으로 설정하고 기존 방식으로 학습·상태를 확인합니다.
  3. 직접 작성 모듈에서 외부 답변 API를 호출하고, 응답을 기존 변수에 담아 Talk로 표시하도록 구성합니다. 봇 설정에서 이 모듈을 2차 LLM 답변용으로 선택합니다.
  4. 결과 판정 변수, 답변 성공값, 정상 미인식값을 지정합니다. 세 값의 의미는 연결 API의 실제 응답과 맞아야 합니다. 값 누락·정의 외 결과·통신 실패는 정상 미인식과 구분합니다.
  5. 정상적인 1차 미인식이면 2차 모듈이 실행되고, 2차도 정상 미인식이면 기존 미인식 응답 설정이 적용됩니다. RAG·Wiki 지식 관리와 답변 생성은 연결 외부 서비스에서 수행합니다.
  6. 시뮬레이터에서 사전 Q/A, 2차 답변, 정상 미인식, 오류와 추가 질문을 각각 확인합니다. 기존 학습·운영 버전 전환 절차를 그대로 사용합니다.

봇 허브 생성 항목은 일반 생성 화면에서 숨깁니다. 기존 허브의 연결·운영 기능은 유지합니다. 일반 제작자가 다른 사람의 봇이나 학습 자료를 편집할 권한은 생기지 않습니다. 기존 Admin 운영 권한은 유지합니다.

질문하는 사람과 공유방

  • 개인 대화는 각자 기록과 시나리오를 이어갑니다. 공유방은 같은 방 참가자가 질문·답변을 함께 볼 수 있습니다.
  • 공유방에서는 봇을 명시적으로 부른 질문만 실행합니다. 한 질문자가 추가 질문을 포함한 시나리오 전체를 진행하는 동안 다른 참가자는 그 시나리오를 대신 이어갈 수 없습니다.
  • 다른 참가자의 일반 대화는 허용합니다. 클라이언트가 입력창을 잠그지 못하더라도 서버가 다른 참가자의 봇 질문 실행을 거절합니다.
  • End·오류·만료·종료에 따른 기존 차례 해제와 세션 정책을 사용합니다. 다른 방과 개인 대화는 별도로 진행할 수 있습니다.
  • 재접속할 때는 연결 클라이언트가 받은 대화 자격 증명을 유지해야 합니다. 방 주소나 임의 참가자 이름만으로 다른 사람의 대화에 접근할 수 없습니다. 자격 증명은 다른 사람에게 공유하지 마십시오.

연결 클라이언트와 템플릿

대상은 Webchat·카카오톡·Teams·Slack·Discord·Telegram·Google Chat·LINE입니다. 기존 채널에서 CGA 대화를 호출하는 구조를 사용합니다. 새 클라이언트는 연결 측에서 이벤트를 검증하고 기존 질문 API와 공유 SDK를 사용해 연결합니다. 채널 이름을 등록하는 것만으로 실제 연결이 완료되지는 않습니다.

Admin의 기존 템플릿 화면에서 해당 채널을 선택하고 저장한 뒤, Talk에서 채널별 템플릿을 구성합니다. Slack·Discord·Telegram·Google Chat·LINE의 지원 표현은 text/button/card/table/link-button/carousel 여섯 가지입니다. Webchat의 Rich Form 등 기존 표현은 계속 제공합니다. 플랫폼마다 지원하지 않는 표현은 명시 오류로 처리하며, 원문을 조용히 잘라 성공으로 표시하지 않습니다.

  • Slack·Google Chat의 스레드, Discord 채널/스레드와 Telegram 주제는 연결 규격에 맞춰 방을 구분합니다.
  • 선택 버튼은 원본 메시지를 확인해 값을 복원합니다. 이미 처리한 이벤트는 저장한 결과를 복구하고, 새 이벤트로 과거 카드를 누르면 거절합니다.
  • LINE은 한 번만 쓸 수 있는 reply token의 수신 시각과 사용/결과불명 상태를 연결 클라이언트가 관리해야 합니다. SDK는 만료 등을 검사해 게시 packet을 만들며, 실제 게시를 대신하지 않습니다. 처리 후 packet 준비가 실패해도 받은 CGA 응답은 보존합니다. 같은 질문을 자동 재실행하거나 push로 전환하지 않습니다.

확인된 범위와 사용 전 확인

개발 검증의 합성 이벤트·로컬 HTTP·전용 QA PostgreSQL·브라우저 결과는 실제 메신저 송수신 성공과 구분합니다. 실제 외부 LLM과 카카오톡·Teams·Slack·Discord·Telegram·Google Chat·LINE 왕복은 인수 단계에서 확인해야 합니다. 앱 설치·서명·권한·Secret·플랫폼 게시·비용은 별도 준비와 승인이 필요합니다. 실제 플랫폼의 입력창 잠금·이미지 접근성·응답 토큰 유효성도 해당 플랫폼에서 확인합니다.

400개 합성 참가자 시험은 서버 질문 차례·일반 대화 보존·방 격리를 확인하는 시험입니다. 실제 400명이 접속한 메신저의 성능·용량을 증명하지 않습니다. 지속 LLM 대화 샘플은 보류 상태로 이 안내의 사용 기능에 포함하지 않습니다. 접속 URL과 배포된 기능 버전은 담당자가 제공한 현재 개발환경 확인 결과를 따르십시오.
